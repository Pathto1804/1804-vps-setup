# 0003 — 单入口 TUI 与原生系统状态

- 状态：已接受（2026-11-16）
- 取代：[0001](0001-no-orchestrator.md)（无编排器）、[0002](0002-script-consolidation.md)（脚本合并与步骤号前缀）
- 关联：[docs/codewiki/architecture.md](../codewiki/architecture.md)、[docs/codewiki/terms.md](../codewiki/terms.md)（交互契约 / 原生状态 / 标准初始化）

## 背景

ADR-0001 把交付形态定为「raw 单文件 + 自包含 + 无编排器」，代价是 7 个脚本各带一份公共块拷贝、顺序只能靠人按 README 保证、跨脚本参数靠项目私有的 `/root/.vps-init.conf` 传递。ADR-0002 把脚本数从 8 降到 6 后再加 `08`，仍留下三个结构性问题：

1. **入口分散**：用户要先读 README 才知道该跑哪个脚本；重跑、续接、维护各走不同文件。
2. **私有运行态**：`/root/.vps-init.conf` 记录端口、用户、公钥、参数。它与系统真实状态可以不一致（改过 sshd 却没改 conf、删了 conf 就丢失"旧端口"记忆），而 `12-verify.sh` 的结论依赖它，等于用缓存判断真相。
3. **无法整体引导**：跨步骤的「已达标就跳过」只能靠人记，重复运行会无谓重写配置。

需求变化：启动即进入交互式 TUI，主菜单 `0` 按现有顺序引导标准初始化；状态从系统原生配置与实时状态读取。

## 决策

1. **单一 raw 入口 `00-tui.sh`**。所有能力（更新、用户、UFW/SSH、fail2ban、Swap、BBR、终检）并入一个自包含脚本；不再保留步骤脚本或转发壳。启动只做环境前置检查（root / TTY / 发行版）与状态探测，不安装软件、不初始化系统、不写文件。
2. **以系统原生状态取代项目私有状态**。删除 `CONF` 与全部 `conf_*` 读写，不迁移、不读取、不创建、不自动删除旧 VPS 上的 `/root/.vps-init.conf`。数据来源固定：`sshd -T`（有效配置）、`ss -tlnp`（监听）、`ufw status numbered` / `ufw show added`（规则）、`~/.ssh/authorized_keys`（公钥）、`passwd -S`（密码）、`sudo -l -U`（有效 sudo 权限）、`fail2ban-client status sshd` + `/etc/fail2ban/jail.local`、`/proc/swaps` + `/etc/fstab`、`sysctl`、`/etc/apt/apt.conf.d/20auto-upgrades`。服务所需的原生配置文件仍照旧创建与修改——它们是服务的持久状态，不是本项目的缓存。
3. **主菜单固定编号**：`0` 标准初始化、`1` 换源说明、`2` 系统更新与基础工具、`3` 时区、`4` 用户、密码、sudo 和密钥、`5` UFW 与 SSH、`6` fail2ban、`7` Swap、`8` BBR、`9` 终检与报告、`q` 退出。每个功能编号只打开状态页/子菜单，进入不触发任何写操作，必须再显式选动作。
4. **Bash 内置 ANSI 清屏**，不依赖 `dialog` / `whiptail`。仅当 stdout 是 TTY 且 `TERM` 可用、非 `dumb` 时清屏：启动绘制菜单前、切换页面前、用户确认看完动作输出后。动作输出、错误诊断、云平台/双闸门提示在用户确认前不清屏；无效输入不整页重绘。
5. **`08` 的交互风格降级为模块**：Swap 段保留其自有 helper 与 `set -uo pipefail`（不开 `-e`），私有符号统一 `swap_` 前缀，由无参数 `run_swap_menu()` 在子 shell 中关闭 `-e` 与 ERR trap 并安装原有 EXIT/INT/TERM 清理语义，选项与 trap 不外泄到主 TUI。
6. **动作隔离**：菜单动作统一经 `act` 调用（临时关闭 `-e` 与 ERR trap，动作内每个危险步骤显式 `|| die_action` / `if !` 判错），保证 TUI 在动作失败后仍然存活。启动前置检查与输入中断仍用 `die`（进程已无法继续）。

## 被否的替代方案

1. **保留 7 个脚本，另加一个 TUI 总控**：总控必须 `source` 或调用其余脚本，与 raw 单文件交付冲突；同时保留两份实现，`sync_check` 的公共块比对继续膨胀。否决。
2. **TUI 只做菜单、动作仍转发给旧脚本**：即"壳"方案。旧脚本各自重跑前置检查与首次运行逻辑，状态页与动作会看到两套口径；且转发壳在 raw 形态下无法定位同级文件。否决。
3. **保留 `/root/.vps-init.conf` 但只读不写**：看似兼容旧 VPS，实际让"以系统状态为准"与"以缓存为准"两套口径并存，`12-verify` 的旧端口核验就成了不可信结论。否决。
4. **用 `dialog` / `whiptail` 做界面**：需要额外包，且会把动作输出吞进弹窗，闸门提示与 ufw 原始输出反而更难读。否决。
5. **把业务端口清单继续存起来做收敛**：清单是私有状态，与"直接管理原生 UFW 规则"冲突；改为端口菜单直接查看/添加/删除规则，首次初始化时只问一次额外端口。否决保留清单。

## 后果

- **失去的能力（有意）**：进程中断后不再自动推断/清理历史旧 SSH 端口规则；`12` 不再声称能核验"旧端口已关闭"，改为在报告里完整列出 ufw 规则并要求人工核对。旧 VPS 上的 `/root/.vps-init.conf` 不迁移、不读取、不删除。
- **保留的能力**：三条防锁死铁律、双闸门、`backup_file` 备份与 `bk_prune` 保留策略、fail-closed 端口校验、fstab 校验回滚、`/root/vps-init-report.md`。
- **`tools/sync_check.sh` 收缩**：不再比对跨脚本公共函数、`CONF`/`BK_ROOT` 多文件一致性与旧 UI 原语；保留入口唯一性与旧脚本不得复活、`shopt -s inherit_errexit` 关键行、包清单与 README/教程一致、私有状态文件不得复活。
- **`00-tui.sh` 成为唯一能锁死登录的文件**，改动必须真机全链路验收：两道闸门 + 新终端密钥登录 + 终检全绿。
- 单文件约 2800 行，审查成本上升。**触发重评的条件**：`00-tui.sh` 超过约 4000 行，或出现必须按发行版分叉的大段逻辑（届时按「动作模块 + 生成器产出单文件」重新评估，而不是回退到多脚本 raw 分发）。
