# 业务与边界

## 这是什么

给一台刚买来的 Debian（兼容 Ubuntu）VPS 做一次性安全初始化的脚本。目标状态一句话：**只认你的密钥、该关的门都关着、补丁会自己打上**。

使用者的真实场景：拿到 root 提示符，不知道该先开防火墙还是先改 SSH 端口；怕改错把自己锁在门外；希望每一步都有检查点、有退路。入口只有一个：拉下来跑，进菜单，按 `0` 走完全流程，或者按需只做某一项。

## 用户与定位

- **个人自用**，不是通用产品。参数（BBR 调优、端口、工具集）基于作者自己的机器和线路。
- 不承诺向后兼容、不提供支持 SLA、不面向自动化批量部署。
- 直接使用者的技能假设：会用 SSH、能读懂 shell 脚本、知道 Snapshot 是什么。

## 交付形态

| 形态 | 命令 | 说明 |
|---|---|---|
| 主入口（默认） | `sudo -i` 后 `bash <(curl -fsSL <raw URL>/00-tui.sh)` | 单文件拉到内存执行，不落仓库、不预装 git |
| 固定版本 | 把 URL 里的 `main` 换成 tag | 同一条命令 |
| 本地副本（可选） | `git clone` 后 `bash 00-tui.sh` | 行为完全相同，只是脚本来处不同 |
| 弱网兜底 | 本机下载 → `scp` → `bash 00-tui.sh`；或第三方加速前缀 | 加速站是第三方，脚本内容经过中转 |

两种形态**只有一套实现**：脚本自包含，不读取仓库内其他文件，因此本地执行不改变任何行为。详见 README「附：Git 拉取到本地执行（可选）」。

## 支持矩阵

- **一等支持**：Debian 12 bookworm（真机验收基线）、Debian 13。
- **兼容但未逐版本验证**：Debian 11、Ubuntu 20.04+。
- 硬依赖：`sshd_config.d` 目录；`bind9-dnsutils` 自 Debian 11 / Ubuntu 20.04 起提供——更老系统会在装包步骤失败。
- Ubuntu 22.10+ 的 `ssh.socket` 套接字激活会让 `Port` 不生效，脚本检测到就切回 `ssh.service`（Debian 不涉及）。

## 产品边界（明确不做）

- **不保存项目私有状态**：没有 `conf` 文件、没有进度标记。状态一律读系统原生来源；用户输入的偏好只存在于本次运行。旧 VPS 上的 `/root/.vps-init.conf` 不迁移、不读取、不删除。
- **不支持无人值守**：强制 TTY，拒绝 cloud-init/user-data 执行。这是防锁死设计，不是缺陷。
- **不代改时区与 NTP**：标准初始化只检查并给命令，达标才继续——这两项属于系统基础设置。
- **不安装 Docker**：只给提示与推荐第三方脚本。
- **不装诊断类提权工具**：tcpdump / strace / sysstat 按需再装。
- **不自动回滚**：改配置前备份到 `/root/vps-init-backups/`，恢复靠人工（两处例外见 [architecture.md](architecture.md#失败与恢复语义)）。
- **不自动猜测历史旧 SSH 端口**：进程中断后不推断"哪条规则是旧端口"，终检把规则全列出来由人核对。
- **不按清单收敛业务端口**：没有 `ALLOWED_PORTS` 清单，端口规则直接增删；首次初始化只问一次额外端口。

## 成功标准

1. 菜单 `7` 终检无红灯。
2. 新端口 + 密钥登录可用，root 被拒，旧端口已从 ufw 与云安全组移除（云安全组由人核对）。
3. fail2ban jail 端口等于 sshd 实际端口（否则静默失效）。
4. `/root/vps-init-report.md` 可归档，含当前状态、完整 ufw 规则与检查结果。
5. 重跑不重写已达标的原生配置，也不产生任何项目私有状态文件。
